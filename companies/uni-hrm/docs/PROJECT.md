# Паспорт проекта: Uni-HRM

> Университетская система управления персоналом (Human Resource Management)

---

## 1. Описание и цели

### 1.1. Описание

**Uni-HRM** — комплексная система управления персоналом, разработанная для высших учебных заведений Республики Узбекистан. Система автоматизирует полный цикл HR-процессов: от найма и учёта кадров до расчёта заработной платы, отпусков и генерации отчётности.

### 1.2. Целевая аудитория

- Университеты и институты Узбекистана
- Масштаб: **500–2000 сотрудников**
- Поддержка всех категорий персонала

### 1.3. Категории персонала

| Категория | Аббревиатура | Описание |
|-----------|-------------|----------|
| Профессорско-преподавательский состав | ППС | Профессоры, доценты, старшие преподаватели, ассистенты |
| Административно-управленческий персонал | АУП | Ректорат, деканы, начальники отделов |
| Учебно-вспомогательный персонал | УВП | Лаборанты, методисты, специалисты |
| Хозяйственный персонал | ХП | Техники, водители, уборщики |
| Совместители | — | Внутренние и внешние совместители |
| Почасовики | — | Преподаватели с почасовой оплатой |

### 1.4. Бизнес-цели

1. **Цифровизация HR-процессов** — переход от бумажного документооборота к электронному
2. **Централизация данных** — единый источник истины по всем сотрудникам
3. **Автоматизация рутины** — автоматический расчёт отпусков, зарплат, табелей
4. **Аналитика и отчётность** — дашборды, отчёты, прогнозы для принятия решений
5. **Интеграция с HEMIS** — синхронизация с государственной системой высшего образования
6. **Self-service для сотрудников** — подача заявлений, просмотр данных через личный кабинет
7. **Мобильный доступ** — Telegram Mini App для оперативного взаимодействия

## 4. Архитектурные решения

### 4.1. Базовые модели

```python
class TimestampedModel(models.Model):
    """Базовая модель с временными метками."""
    id = models.UUIDField(primary_key=True, default=uuid.uuid4, editable=False)
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)

    class Meta:
        abstract = True


class SoftDeleteMixin(models.Model):
    """Мягкое удаление вместо физического."""
    is_deleted = models.BooleanField(default=False)
    deleted_at = models.DateTimeField(null=True, blank=True)

    class Meta:
        abstract = True

    def soft_delete(self):
        self.is_deleted = True
        self.deleted_at = timezone.now()
        self.save(update_fields=["is_deleted", "deleted_at"])
```

### 4.2. UUID Primary Keys

Все модели используют `UUID` в качестве первичного ключа вместо автоинкрементных `INTEGER`. Причины:

- Безопасность: невозможно угадать ID записи
- Распределённость: отсутствие коллизий при синхронизации с HEMIS
- URL-безопасность: нет раскрытия количества записей

### 4.3. Audit Trail

Каждая значимая модель регистрируется в `django-simple-history`:

```python
from simple_history.models import HistoricalRecords

class Employee(TimestampedModel, SoftDeleteMixin):
    # ... поля ...
    history = HistoricalRecords()
```

Это обеспечивает полную историю изменений: кто, когда и что изменил.

### 4.4. Soft Delete

Записи никогда не удаляются физически из базы данных. Вместо этого устанавливается флаг `is_deleted=True`. Менеджер `ActiveManager` автоматически фильтрует удалённые записи:

```python
class ActiveManager(models.Manager):
    def get_queryset(self):
        return super().get_queryset().filter(is_deleted=False)
```

## 6. Нефункциональные требования

### 6.1. Производительность

- Время ответа API: **< 200ms** (95-й перцентиль)
- Время загрузки страницы: **< 2s** (First Contentful Paint)
- Поддержка **100 одновременных пользователей**
- Генерация PDF-документа: **< 5s**

### 6.2. Безопасность

- HTTPS обязателен в production
- JWT токены с коротким сроком жизни (15 мин access, 7 дней refresh)
- Rate limiting на login-эндпоинты
- CORS ограничен доменом приложения
- SQL-инъекции предотвращены через ORM
- XSS предотвращён через React-экранирование
- CSRF-защита для session-based auth
- Audit trail всех изменений критических данных

### 6.3. Доступность

- Доступ 24/7 (SLA 99.5%)
- Плановое обслуживание: ночные часы (02:00–05:00 UZT)
- Бэкапы базы данных: ежедневно с хранением 30 дней

### 6.4. Масштабируемость

- Горизонтальное масштабирование через Docker
- Celery workers для фоновых задач
- Redis для кеширования и очередей
- CDN для статических ресурсов в production

## 8. Ограничения и допущения

### Ограничения

1. Система не заменяет бухгалтерское ПО — только рассчитывает зарплату и формирует ведомости
2. Не является системой электронного документооборота общего назначения
3. Первая версия не поддерживает филиалы университета (single-tenant)
4. Мобильное приложение реализовано только как Telegram Mini App (без нативного приложения)

### Допущения

1. У университета есть аккаунт в HEMIS
2. Сотрудники имеют доступ к Telegram
3. Доступен сервер для развёртывания Docker-контейнеров
4. HR-отдел готов к переходу на цифровой документооборот
